# Step 2: Security

This is the security assessment of an ACTIVE INCIDENT, running before any fix. Do not edit any file. Determine whether this is a security event: were credentials, tokens, or data exposed; is anything still reachable that should not be; does the containment action Dev is about to take destroy evidence that matters. Say plainly whether credentials need rotating and whether the incident must be treated as a breach. Quote what you relied on — this becomes the record. Dev acts on your assessment next, so lead with the action items.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
