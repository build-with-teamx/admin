# Step 2: Security

This is the security pass of a READ-ONLY audit — do not edit anything. Assess the surface under audit for threat exposure: authorization boundaries, permission checks, secret handling, data exposure, injection surfaces, and anything that trusts input it should not. Each finding needs evidence (file and line), the consequence, a priority, and a practical recommendation, and you must separate what you observed from what you infer. You do not own a pass/fail verdict — report findings for the report.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
