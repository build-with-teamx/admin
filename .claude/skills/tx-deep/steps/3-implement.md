# Step 3: Dev

This is the implementation step of a DEEP run — the work was judged complex or high-impact, which is why Discovery and Architect ran first. Implement the Architect's plan as written: the named files, the named functions, the stated order. Where you must deviate, do it and then say exactly what you changed and why in your report — a silent deviation makes every later step reason about code that does not exist. Reuse the existing patterns, components and utilities already in the repo. Security, Performance and Review all inspect what you produce, so leave the working tree holding only this change. Do not open a PR or push — a later Release step owns all git operations. Do not run the build, dev server, or full test suite.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
