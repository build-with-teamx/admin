# Step 3: Review

Review the fix on disk for correctness, completeness and quality. Run any relevant existing tests and inspect the changed files. Report a clear verdict (pass / needs-fix), specifically checking: (1) the fix addresses the ROOT cause rather than papering over the symptom, and (2) a regression test exists that would have caught this bug before the fix. Missing either one is needs-fix. If the TeamX architecture freshness report says a mapped document is stale, also return needs-fix so Development updates TEAMX.md or that authoritative document. Do not edit files in this review step and do not restate the diff.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
