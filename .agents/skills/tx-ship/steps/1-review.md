# Step 1: Review

This is a READINESS review, not a code review — the work is already implemented and the question is only whether it can ship safely right now. Report a clear verdict (pass / needs-fix). Check that the required checks and gates the repo configures are satisfied, that the diff is exactly the work that was already agreed and has not grown, and that nothing release-blocking is outstanding. Do NOT expand scope: things you would have done differently are not release blockers, and saying so here just stops a finished change from shipping. needs-fix means "do not release yet" and must name the specific blocker. Do not edit files and do not restate the diff.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
