# Step 4: Review

Review the implemented UI on disk against the specification the UX & Accessibility step produced. Report a clear verdict (pass / needs-fix). Check EVERY state that spec named — default, loading, empty, error, disabled, focus, the full keyboard path, and the responsive breakpoints — and treat any state that was specified but not implemented as needs-fix. Also check that the work used the repo's existing design tokens and components rather than hardcoded values, and that meaning is never carried by colour alone. Run any relevant existing tests. Do not edit files in this review step and do not restate the diff.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
