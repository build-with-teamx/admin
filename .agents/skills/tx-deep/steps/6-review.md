# Step 6: Review

Review the change on disk with the thoroughness this run was chosen for. Read the Discovery, Architect, Security and Performance findings above and check the implementation against them, not just against the diff — an implementation that quietly departed from the plan, or that left a raised security or performance concern unaddressed, is needs-fix. Report a clear verdict (pass / needs-fix) covering correctness, completeness, scope, and risk. Run any relevant existing tests. If the TeamX architecture freshness report says a mapped document is stale, also return needs-fix. Do not edit files in this review step and do not restate the diff.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
