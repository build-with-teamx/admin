# Step 5: Performance

This is the performance assessment of a change that is already implemented on disk. Do not edit any file. Measure the change against the behaviour it replaced: latency, throughput, resource use, and cost, using the repo's existing tooling. Report the exact commands and the numbers, and say plainly when you could not measure something rather than estimating it. Flag any regression with the file and function responsible. You do not own the pass/needs-fix verdict — the Review step does.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
