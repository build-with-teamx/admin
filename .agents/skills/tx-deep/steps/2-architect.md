# Step 2: Architect

This step is read-only: you must not edit files.

This is the design step, between investigation and implementation. Your ONLY job is to decide HOW the change gets made — do NOT edit any file. Define the boundaries, the data flow, the interfaces, and any migration or ordering constraint. Where a real choice exists, compare at most two options and give the trade-off in one line each; do not enumerate alternatives nobody will pick. Then write a file-level implementation plan the Dev step follows verbatim: the named files, the named functions, and the order of edits. Reuse what the repo already has rather than introducing a new pattern — say which existing pattern you are following. The Dev step runs next on a different engine and sees only this plan, so anything you leave implicit is lost.

Finish with a short report for the next step: what you found or changed, files touched, checks run and their result, and a verdict line `VERDICT: done | blocked | needs-fix`.
